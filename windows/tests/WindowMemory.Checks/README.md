# Windows 窗口资源与内存检查

运行真实 `AppController`、设置窗口、桌宠窗口和小铺视图。所有业务 HTTP 在内存中拦截，不建立网络连接；使用独立临时身份及目录，不读取正式设置，不修改正式启动项。窗口放在屏幕外。

```powershell
dotnet run --project windows/tests/WindowMemory.Checks -c Release -- --output=C:/temp/window-memory.json
```

检查设置隐藏/最小化与恢复、日常记录变更、未发送草稿保留、列表更新、桌宠隐藏释放与恢复、隐藏期间脚本动作结束，以及封面解码尺寸、长宽比例、文件句柄释放。小铺窗口隐藏后，付款轮询计时器仍需保持运行；该检查不模拟真实支付到账。

记录桌宠单独运行、设置打开、日常页、隐藏、最小化和多次恢复后的进程私有字节、工作集与托管存活对象；另记录 30 次状态通知期间的总分配字节。性能数字仅用于本机前后对照，不作为 CI 的固定阈值。CI 以生命周期和行为断言判断通过与否。

`--baseline` 只关闭新行为断言，用于旧 DLL 的对照。为了让两边操作完全相同，应先保存旧客户端 DLL，再将同一份已构建检查程序复制到独立目录，在副本中替换 `ZhuoDazi.dll` 为旧 DLL 后运行 `dotnet WindowMemory.Checks.dll --baseline`；修改后的版本运行正常模式。不要在用户安装目录做文件替换。

同一机器至少运行三对独立进程，以中位数比较。进程快照前使用相同的 GC 稳定步骤，仅存在于测试中；生产代码没有强制 GC、清空工作集或伪造任务管理器数字。WPF 原生缓存、图像大小、DPI、数据数量和加载的页面会影响结果；这些数据不是用户当前正式进程的实时内存，也不等于整个客户端在所有场景的收益。
