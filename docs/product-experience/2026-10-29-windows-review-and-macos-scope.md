## 二、Windows 界面与使用体验

### 1. 桌宠小铺

- 独立菜单统一叫“桌宠小铺”。顶部两个标签为“桌宠图鉴”“小剧场 / 互动词库”。

- 保留左右区域各自纵向滚动；窗口较窄时允许横向滚动，不切成上下布局。
- 卡片显示角色名称、简介、素材数量、价格、标签、精选/默认标记和拥有状态；支持搜索、全部/免费/付费/已拥有筛选。
- 商品名称和介绍按真实场景展示；独立本地预览环境仍保留必要的环境提示，避免与正式版混淆。

### 2. 桌宠小窝

- “我的图鉴”统一展示本地 GIF 目录与已安装的小铺桌宠，使用复选框启停。
- 不再显示完整目录路径，也移除了下方“当前目录”路径框。
- 本地条目显示“角色名称 + 本地桌宠”；小铺条目显示“角色名称 + 小铺桌宠 · N 个动作”。
- 选中列表行不等于启用，启停由复选框或对应启用按钮控制。
- 删除本地目录绑定不会删除原文件夹。
- 大小滑块由 140–300 调整为 **60–300**，保存后重启继续有效。

### 3. 小剧场 / 互动词库列表

改为统一资源卡片，区分小剧场与词库的颜色和类别，突出名称、简介、免费标识和安装/启用状态。支持搜索、分类筛选及清除筛选；宽窗口双列，窄窗口单列。

操作状态明确区分为“免费安装”“已安装 · 待启用”“启用”“停用”。安装完成不会自动打开内容运行开关。

### 4. 搭子、大厅与小剧场节奏

- 私人搭子发送间隔为 **1 秒**，普通大厅为 **15 秒**；服务端分别计时，大厅冷却不会占用私人搭子的发送间隔。
- 大厅文字按长度停留 **12–20 秒**，气泡与来访窗口时长一致，便于读完。
- 小剧场按主角、搭子的先后顺序逐句说话，前一句结束后再开始下一句；每句按长度停留 **5–12 秒**。

2026-10-30 补充私人搭子离线投递确认：

- 从搭子页、托盘或菜单点击发送时，先读取对方最新在线状态。在线时直接发送；离线时弹出“对方当前不在线，是否继续发送？”，提供“继续发送 / 取消”，默认取消。
- 继续发送后沿用离线来访队列，对方上线后可接收，未接收内容保留 24 小时，最多积压 3 条；取消不会发送，也不显示发送成功。成功提示只表示已发出或进入待接收队列，不表示已经阅读。
- 私人搭子的在线状态按最近 90 秒内的主动服务请求判断，独立于大厅开关。退出大厅后仍能作为私人搭子保持在线，不会因此重新公开到大厅。刚退出应用或断网时，状态最多有约 90 秒的判定延迟。
- 如果后端尚未提供状态字段，显示“状态待确认”，发送前说明暂时无法确认在线状态并询问是否继续；读取状态失败时提示连接问题，不自动发送。
- Windows 和 macOS 使用相同规则。此次更新限本地代码与联调环境，不发送真实消息，不上线；macOS 尚需 Mac 原生编译和实机验收。
- 停止剧场或退出时能取消等待并清理气泡；接收队列等原有机制保留。

## 四、商品、付款与已购恢复

### 1. 商品与权限

- 一个收费商品对应一个角色包，含同一角色的 25+ 动作或表情；不是 25 个不同角色。
- 价格由后台设置，本轮按普通款 **¥2.80**、复杂或热门款 **¥5.80** 准备内容；也可以设为免费。
- 后台可指定一个免费且已上架的默认角色。默认款不会覆盖用户已经选用的桌宠。
- 每个包只开放部分预览：后台挑选素材，或开放前五个；购买前不能拿到完整包。
- 游客和试用用户可以浏览及预览；点击购买或领取先提示正式激活，不创建订单。激活成功后再次点击才继续。
- **小铺桌宠即使免费，也需要正式激活才能领取、下载和使用。** 内置桌宠的试用体验保留。
- **小剧场 / 互动词库下载免费，不走订单和支付。** 实际运行沿用现有体验/激活规则，不额外收取资源费用。

### 2. 付款流程

1. 用户选定收费角色，点击购买；服务端创建订单，锁定账号、商品版本、金额及收款信息。
2. 显示五位备注码、金额、收款方和倒计时。短码格式为 **三个数字 + 两个英文字母**，例如 `123AB`；不区分大小写，保留前导零。
3. 当前采用好友转账：收款昵称“小王”，微信号 `wcl_lcw627`。可复制短码与微信号，信息由后台配置。
4. 用户在微信转账说明中填写完整短码，金额与订单一致。普通聊天文字不能代替转账说明。
5. 按已确认规则，监听识别到匹配收款账号、金额、短码、交易标识及有效时间的个人转账消息，即确认订单成功、发放权益，**不等待额外点击收款**。
6. 客户端同步到付款成功后自动下载、校验并安装，显示成功；**不自动启用**，由用户自行选择。
7. 15 分钟内未完成的订单记为已过期并收起付款区域；订单记录保留，软件主窗口不关闭。

收款码保留为后台可选方式，按收款核对流程处理；当前主流程使用好友转账，规避用户实测的收款码重复备注受限问题。监听不可用时提示等待恢复，不能把尚未确认的订单显示为成功。

五位短码只用于关联订单，不是下载密码，也不是可解密的账号凭据。账号权益与签名授权负责控制完整资源的下载和使用。

### 3. 用户订单与安装

- 图鉴页提供“订单记录”入口，点击打开独立弹窗。
- 待付款、已付款、已取消、已过期订单长期保留；可查看金额、备注码、锁定版本和各时间记录。
- 已付款订单显示付款验证结果和本机安装状态；失败可重试，相同已安装版本不重复下载。
- 用户进入小铺后，切换页面或隐藏设置窗口仍可继续同步订单；退出软件后停止，重新进入小铺恢复同步。
- 权益按账号保存，本机安装与启用状态单独管理。重新下载不需要靠备注码证明已购买。
- 安装前校验授权、签名、包及文件完整性；首版桌宠包使用 GIF 素材，不执行第三方插件代码。

### 4. 本地转账信息怎样进入正式后台

使用现有专用 HTTP API，由收款电脑上的监听程序主动向后台发请求。用户的 Windows/macOS 客户端只向后台下单和查询状态，不直接连接收款电脑，也不需要读取微信消息。

```mermaid
flowchart LR
  A[收款电脑上的 wxlocal] --> B[本地付款监听程序]
  B -->|HTTPS 上报转账事件和心跳| C[正式后台 API]
  C --> D[匹配订单并记录付款权益]
  D --> E[Windows / macOS 查询订单]
  E --> F[自动下载安装，用户手动启用]
```

| 现有接口 | 作用 |
| --- | --- |
| `POST /api/pet-market/payment-events` | 上报金额、币种、五位备注码、交易标识、收款账号标识及时间；后台校验、去重并匹配订单 |
| `POST /api/pet-market/payment-heartbeat` | 上报监听是否可用；后台以收到时间维护 60 秒有效期 |
| `GET /api/pet-market/orders` | 已激活客户端同步自己账号的订单，付款成功后按权益下载 |

桥接请求使用独立 Bearer 令牌认证。后台配置项为 `DESKPET_PET_MARKET_BRIDGE_TOKEN` 和 `DESKPET_PET_MARKET_COLLECTION_ACCOUNT_ID`；后者是 wxlocal 识别出的收款账号标识，区别于向用户展示的微信号。令牌仅配置在收款监听端和服务端，不发给普通客户端。

**现状结论：业务协议和监听代码已支持正式 HTTPS，当前运行仍只连接本地。** `scripts/local_market_payments.py` 默认仅接受 `http://127.0.0.1:端口`；显式 `mode: production` 才允许 `https://in.desktoppet.online`，限制 443 端口、正常验证证书并禁止重定向。配置、发送器和队列绑定使用相同校验。不能据此推断线上服务器已经部署本轮代码；本次未访问或验证线上环境。

本轮完成与上线前仍需准备的事项：

1. 已增加明确的正式 HTTPS 上报模式，限定目标域名、正常验证证书、保持禁重定向；本地调试模式继续保留。
2. 正式后台配置专用桥接令牌、实际收款账号及收款设置，并使用正式签名配置；先在隔离环境验证整条链路。

5. 保留断网重试和服务端幂等；状态窗口区分已上报、订单已确认和待核对，长期鉴权/参数错误显示需处理数量。历史已上报但未记录结果分类的事件以后台订单为准，不能补算成付款成功。

## 五、管理后台调整

### 1. 资源上架完整流程

后台新建桌宠 → 设置名称、简介、免费/收费、价格、默认/精选/标签 → 上传本地角色文件夹或多选 GIF → 设置版本和部分预览 → 校验后上架 → 桌面客户端刷新后展示。

后台负责生成资源清单与安装包；原有 ZIP 上传方式继续可用。可修改商品信息和上下架，已有订单的金额、版本及收款信息不会随后台修改而改变。

剧场和互动词库沿用“资源包”管理：上传 ZIP，填写分类、名称、简介、版本及上架状态；客户端提供免费安装和手动启用。

**正式资源运营由用户负责：** 正式上线后的角色素材、剧本、词库由用户自行上传；名称、价格、免费/收费、默认款、精选、标签、预览内容和上下架由用户自行调整。本次开发提供这些后台能力和操作说明，不代用户准备或上传线上商品，不把本地样例作为正式资源迁移。

## 八、卸载反馈（已加入本次开发）

### 1. Windows 卸载流程

- 在正常卸载流程提供可选理由：“不常用”“占用资源”“体验问题”“暂时不用”“其他”；选择“其他”可补充最多 500 字说明。
- 提供“确认卸载”“跳过反馈并卸载”和取消；反馈不强制，不阻止卸载。
- 选择取消或仅打开反馈时，不标记卸载成功。完成阶段能够确认卸载成功后，再尽力上报完成事件和所选原因。
- 上报有短超时，断网或失败不阻止卸载；没有收到可信完成报告时，后台不猜测已卸载。

### 2. 后台记录与重装恢复

- 记录设备号、账号/昵称、平台、版本、原因、可选说明、事件时间与收到时间。
- 状态区分“卸载意向/反馈”“已报告卸载”“重装后恢复使用”；离线、关机、休眠单独按活跃状态处理。
- 使用安装批次及事件唯一标识处理重复、迟到事件，避免旧卸载记录覆盖重装后的状态。
- 重新下载安装包本身不恢复状态；确认新安装批次并成功联网启动后才恢复，保留卸载历史。
- 普通覆盖升级不算卸载；卸载不删除购买权益，也不自动释放设备授权名额。
- 后台增加卸载记录、状态筛选和详情，能查询某设备的反馈及恢复历史。

### 3. macOS 对应范围

macOS 纳入应用内“卸载与反馈”入口和明确的卸载指引，并使用同一后台记录体系。提交反馈只表示用户意向；只有可确认完成的受控卸载流程才上报完成。

本轮已实现随 App 打包的独立卸载助手：用户确认后等待主程序退出，仅将已验证的当前 App 移入废纸篓；确认成功后清理对应安装批次，并使用一次性完成凭据上报。反馈请求或网络失败不阻止本机卸载。密钥串中的账号身份和已购权益不随卸载删除；下一安装批次联网启动后恢复后台状态。

用户直接将应用拖入废纸篓、强制删除或离线删除时，应用通常无法保证执行回调，因此不能承诺所有 macOS 卸载都能检测。未确认的路径保留反馈/最后活跃记录，不冒充“已报告卸载”。后续实现与验收必须保留这个平台边界。
