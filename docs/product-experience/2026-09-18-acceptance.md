# 桌搭子产品优化：实施对照与手动验收

日期：2026-09-18。交付状态：本地待验收，未提交、未推送、未部署、未发布。

本轮基于《产品审查与功能清单-2026-09-18》处理 P1 问题、部分 P2 体验改进，以及追加的四项要求。桌面本地版本为 **3.2.10**，Android 为 **1.3.12 / versionCode 16**。原审查报告保留为改动前快照；当前行为以本说明与本轮代码为准。

## 1. 四项明确要求的前后对照

| 要求 | 改动前 | 本轮完成的行为 | 验证重点 |
|---|---|---|---|
| 体验版向在线用户发送桌宠 | 大厅资料和发送接口要求正式激活，客户端入口也限制体验用户 | 有效七天体验、正式激活均可主动加入大厅，选在线成员、预览 GIF、填写留言并发送；过期体验仍有明确限制 | 体验→体验、体验→正式、正式→体验三种组合；到期后拒绝发送 |
| 大厅单独菜单、列表美化 | 大厅混在搭子页，社交范围和发送对象不够清楚 | Windows 设置与托盘独立入口；macOS 独立窗口及菜单入口；Android 底部独立“大厅”，私人搭子在“我的”中单独进入 | 昵称头像、在线标记、人数、选中状态、收件人、空列表、错误重试和冷却提示 |
| 检查更新不计统计 | 更新轮询进入 API 使用量，影响判断 | 采集层与存储层都跳过 `/api/update/latest`；历史接口列表和接口总数排除该路径；真实安装包下载仍计数 | 连续检查三端更新时业务 API 总数不增加，正常业务与下载继续统计 |
| 更新说明让用户能看懂 | 通用说明过于笼统，发布与文档容易脱节 | 编写桌面与 Android 对应版本说明，描述能做什么、解决什么问题、权益差异；发布流程要求提供对应说明文件 | 查看应用更新页长文可读，发布说明与对应版本、平台一致 |

**权限边界**：公开大厅与私人搭子是不同功能。私人绑定、解绑和向私人搭子发送仍需正式激活。体验用户不获得可使用的私人搭子码。新大厅档案默认关闭；旧账号此前选择加入或退出的状态保留，不被新设备覆盖。

| 原编号 | 本轮处理 | 涉及范围 |

| P1-08 功能说明不一致 | 更新三端权益表、版本、词包说明、大厅与私人搭子区别、摸鱼条件、默认规则 | 功能文档、平台说明 |

来访可靠性另补了两条边界：切换正式授权时隔离待看来访；同设备从体验期首次正式激活时衔接体验期队列。后端同时迁移体验昵称、大厅选择、待收投递和设备收取回执；加入已有账号时保留原账号昵称和大厅开关。

暂停一小时的含义：暂缓主动台词、自动互动、自动剧场及来访展示；不改变用户保存的自动开关，不拦截手动操作和到点提醒。暂停有截止时间并保存在本机，重启后按剩余时间继续。它不是暂停桌宠进程或系统级免打扰。

## 5. 先做这组手动验收

### 5.1 当前 Windows 离线界面验收窗口

窗口标题为“桌搭子 · 离线界面验收（独立临时数据）”。它使用真实设置窗口与模拟网络响应，不会向真实用户发送消息，也不会使用已安装应用的设置文件。

- [ ] 左侧有独立“桌宠大厅”，托盘菜单也能直接打开。
- [ ] 初始未加入，说明能看懂；未选收件人时不能发送。
- [ ] 加入后显示 4 位示例用户，头像、在线状态、选中高亮清楚。
- [ ] 点不同成员，发送区域跟随显示正确昵称；GIF 预览与当前桌宠一致。
- [ ] 填留言并发送，结果明确显示收件人，按钮出现倒计时，倒计时结束后恢复。
- [ ] 缩小窗口后仍能滚动到发送按钮；长昵称、说明和反馈内容不被裁掉。
- [ ] 私人搭子页面说明需要正式激活，与体验大厅规则一致。
- [ ] 反馈记录双击或按回车后能读完整回复，可选择复制。
- [ ] 日常台词、暂停一小时、立即恢复的文案能明确表达效果。

离线窗口不启动真实桌宠计时器，不用于验证真实网络、到点提醒、来访动画、统计入库或更新下载。通过这套临时程序自己的托盘菜单“退出桌搭子”退出；关闭设置窗口只会隐藏。

### 5.2 新版客户端配合新版后端的联调

用两台测试设备或两个独立测试身份完成下表。三端组合建议各覆盖一次：Windows↔Android、Windows↔macOS、Android↔macOS。线上后端仍为旧代码时，不能用它判断新版体验大厅接口是否正确。

| 编号 | 操作 | 预期结果 |
|---|---|---|
| H01 | 两端都处于有效体验，主动加入大厅 | 互相看到昵称/在线状态，可以互发 GIF 与留言 |
| H02 | 一端体验、一端正式激活，双向发送 | 两个方向都成功；私人绑定依然需要正式激活 |
| H03 | 未加入→加入→退出→刷新另一端 | 默认不出现；加入后出现；退出后不再是新陌生来访接收对象 |
| H04 | 已有账号在 A 设备关闭大厅，再在 B 设备首次打开 | B 不自动重新开启大厅 |
| H05 | 发送后立刻再发；给同一接收人积压投递 | 30 秒内拦截；达到待收上限后说明原因，不吞掉留言 |
| H06 | 接收方隐藏/穿透/暂停，发送 3 条，再重启恢复 | 依次展示，不被后到的一条覆盖；设备回执与真正看见区分 |
| H07 | 有未看来访时切换正式账号，再切回 | 不展示别的账号来访；原账号待看内容仍保留 |
| H08 | 体验期收到来访，尚未看时首次正式激活 | 本机待看内容、服务端待收投递衔接；加入已有账号不覆盖原昵称/大厅选择 |
| H09 | 断网、目标离线、保存失败或体验到期 | 有清楚错误，控件能恢复，保存失败不错误确认设备收取 |
| Q01 | 开启暂停；手动互动；等提醒到点；立即恢复 | 自动消息与来访暂缓，手动操作和提醒可用，恢复后正常继续 |
| Q02 | 仅关闭日常台词，保留随机互动设置 | 普通待机/动作台词停止，其他功能按各自开关执行 |
| P01 | 关闭自动换宠后连续手动换几只，重启 | 自动开关保持关闭；当前形象名称、来源与实际 GIF 对得上 |
| R01 | 在 23:55 新建“10 分钟后”提醒 | 日期为次日 00:05，不立即触发；过去的一次性时间无法保存为启用 |
| R02 | macOS 演剧场时提醒到点；再隐藏/恢复 | 提醒排队，随后展示；每日提醒仍按原定本地时刻运行 |
| C01 | 新装联网、旧账号新设备、断网后恢复 | 远程默认只初始化未设置项；已有互动偏好不被回写覆盖 |
| C02 | 三端同步互动内容，Android 使用新词包 | 六类内容请求成功；词包文件失效时有有效回退 |
| U01 | 基础版、有效体验、正式版分别检查更新 | 可检查各自可用渠道；更新说明可读；真实下载仍校验签名/散列 |
| A01 | 后台记录 API 总数，连续点三端检查更新 | API 总数、接口排行不新增更新检查；真实下载与业务操作仍计数 |

手机还需要验证：悬浮权限首次授权返回、穿透后的通知恢复、系统杀后台和旋转屏幕后状态。Mac 需要验证菜单栏入口、最小窗口尺寸、Apple Silicon/Intel 构建以及通知权限。Windows 需要验证托盘、Ctrl+Shift+P、休眠恢复和高 DPI。
