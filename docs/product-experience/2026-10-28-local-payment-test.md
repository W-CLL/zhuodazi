# Windows 本地 0.01 元付款联调

日期：2026-10-28。用途：在本机验证下单、微信备注、好友转账自动确认、收款码人工核对和测试包下载。未部署、未推送、未更新线上版本。

## 当前范围

- 独立 Windows 调试窗口，不经过正常客户端的激活、更新、心跳或大厅启动流程。
- 本地服务只监听 `http://127.0.0.1:18765`，测试商品固定 1 分。客户端和收款桥接禁用代理及 HTTP 重定向。
- 备注码固定 `[0-9]{3}[A-Z]{2}`，如 `123AB`；大小写无关，保留前导零，历史不复用。总计 676000 种组合，分配失败明确报错，不擅自扩长。
- 服务端生成订单并确定 15 分钟有效期；同一测试账号和商品复用待付款订单。到期关闭收款面板，主调试窗口保留。
- 支持收款码通知和好友转账卡片两种识别来源。按用户最新确认，仅 `personal_transfer / incoming / observed / verified:false` 结构化事件在收款账号、订单短码、金额、币种、稳定交易标识及有效时间严格匹配后，自动记录本地订单 `paid` 并发放一次下载权益，不等待微信领取或人工确认；普通收款码仍走人工核对。短码本身不提供订单查询或下载授权。
- 下载内容是用于验证权限和下载流程的 ZIP 测试包，**不是包含 25+ 动作的正式桌宠商品**。不安装或执行下载内容。
- 普通角色包 2.80 元、复杂或热门角色包 5.80 元、每包同一角色 25+ 动作/表情，仍属于正式市场规划；卸载反馈和词库多套启用仍按[联合需求](2026-10-28-uninstall-wordpacks-pet-market-requirements.md)规划。

## 启动与停止

使用 PowerShell 7。当前机器的 wxlocal 项目根为 `D:\code_file\pro_python\wxlocal`，其 Python 虚拟环境和已存在的密钥文件供监听使用。启动器从当前微信进程的账号映射定位收款账号，不扫描进程内存或提取新密钥；不能唯一确定账号时会失败并要求指定账号目录。

```powershell
& 'D:\code_file\pro_python\pet\zhuodazi\windows\scripts\start-local-market.ps1'
```

默认构建 Windows Release，然后启动本地服务、收款监听和可见的付款调试窗口。已构建且未改客户端代码时可加 `-NoBuild`。启动器等到监听完成一次成功查询并建立基线，才打开窗口；未就绪会停止本轮启动的服务并报错。

好友转账本轮使用独立目录 `D:\code_file\pro_python\pet\zhuodazi\.local-review\local-market-transfer`，保留原 `local-market` 目录里的已付款订单和测试记录。启动和停止本轮时都指定该目录：

```powershell
& 'D:\code_file\pro_python\pet\zhuodazi\windows\scripts\start-local-market.ps1' -StateDirectory 'D:\code_file\pro_python\pet\zhuodazi\.local-review\local-market-transfer'
& 'D:\code_file\pro_python\pet\zhuodazi\windows\scripts\stop-local-market.ps1' -StateDirectory 'D:\code_file\pro_python\pet\zhuodazi\.local-review\local-market-transfer'
```

以上两行分别用于启动和停止，不需要连着执行。两轮共用本地端口 18765，启动新一轮前应停止上一轮。既有密钥现在需要同时覆盖官方支付通知数据库和转账卡片所在消息数据库，准备阶段会核查覆盖范围。

收款码模式可以用 `-QrImagePath 'D:\实际目录\收款码.png'` 指定本机 PNG/JPG 图片，或直接在窗口内选择图片。好友转账模式无需二维码，当前默认选中该模式。可选参数还有 `-WxlocalRoot`、`-AccountDirectory`、`-KeysFile`、`-StateDirectory`、`-Port` 和 `-NoWindow`。

停止本轮服务与调试窗口：

```powershell
& 'D:\code_file\pro_python\pet\zhuodazi\windows\scripts\stop-local-market.ps1'
```

停止脚本写入共享停止信号，并只关闭进程 ID 和启动时间都符合记录的调试窗口；不关闭微信或已安装的正常桌搭子。订单、候选和日志保留。只关闭付款调试窗口不会停止后台监听，请用停止脚本结束整轮测试。开发时仅重启服务可先执行停止脚本的 `-KeepWindow`，再执行启动脚本的 `-NoBuild -NoWindow`，原窗口和本次付款状态保留。

## 实际测试步骤

### 好友转账

1. 保持收款微信登录，确认监听的官方通知和转账两个来源都已建立基线，窗口显示“本机服务已连接”。
2. 在窗口选择“好友转账”，不需要上传二维码，点击“下单 · ¥0.01”。
3. 用付款方微信在与收款方的聊天中发起 0.01 元转账，转账说明直接填写窗口生成的完整五位短码，如 `123AB`，大小写均可。无需加“备注”前缀。
4. 收款方出现结构化转账卡片后，桥接读取金额、收款人、转账标识和 `pay_memo`。即使尚未点微信里的收款，该消息也可以被识别。普通聊天文字里的金额或短码不算转账卡片。
5. 本地服务按上述个人转账类型严格匹配订单，要求来源消息时间、观察时间和首次接收时间均在订单创建至截止区间内；匹配成功自动记录 `paid` 并发放一次下载权益。客户端轮询后显示“订单已确认，可以下载测试资源包”；不必打开支付识别记录区，也不必点击人工确认。缺字段、不匹配、首次接收已超时或已取消的订单保留待核对，个人转账记录不显示人工确认按钮。
6. 点击下载本地测试 ZIP。实际在微信领取转账是独立操作，程序不代点收款、不发送微信消息；本地测试包不含正式桌宠素材，不会自动安装或执行。

一笔转账的多个生命周期消息按稳定转账标识去重；同一订单收到两笔不同转账也只发一份权益，多余记录保留核对。红包、转出、群聊、收款人不符或备注不完整的记录不用于匹配本次购买。转账标识优先使用 SDK 交易号，缺失时使用单独命名的 transfer_id，不能用消息 ID 冒充转账标识。这里不根据 `pay_subtype` 推断是否已领取、退款或结算，源事件始终为 `observed / verified:false`；`paid` 表示按用户选定的“转出即成功”业务规则放行，`paidAt` 是本地确认时间。

真实卡片允许 `payer_username` 为空：仅在收款人明确为当前账号、私聊来源为聊天 49 类型、发送者非本人且与会话一致时，允许缺少该字段。金额、备注和稳定交易号仍必须匹配；非空但非法的付款人字段不走此兼容分支。

### 收款码

1. 保持收款微信登录，确认调试窗口显示“本机服务已连接”。监听需要已建立基线；查看方法见下节。
2. 在微信准备对应当前收款账号的 0.01 元收款码，保存为本机 PNG/JPG，点击“选择本地收款码图片”。程序只展示所选图片，不会替用户生成微信收款码，也不自行改动图片金额。
3. 点击“下单 · ¥0.01”。窗口显示本次服务端生成的五位备注码、二维码与 15 分钟倒计时。使用窗口给出的完整码；不要自行编造备注或先付款后下单。
4. 使用付款方微信扫码，核对收款人和 0.01 元金额，在微信确认付款前填写该短码。字母大小写均可；桌面复制不会自动把内容送到手机。
5. 付款后展开“本地开发 · 支付识别记录”，点击“刷新支付候选”。桥接默认每 2 秒查询一次；候选列表当前需要手动刷新。
6. 对照微信实际收款记录、金额和备注，选择与当前订单匹配的候选，再点击“确认已到账（仅本地测试）”。对话框默认选“否”。服务端仍会核对收款账号、金额、币种、备注、交易标识与收款完成语义，缺字段或不匹配不会放行。
7. 确认成功后窗口显示“订单已确认，可以下载测试资源包”，点击“下载本地测试包”。下载目标为隔离目录，未确认订单时下载接口拒绝访问；当前真实联调目录的下载验证进展见文末，不将步骤说明视为已验收结果。

到期、取消后收到的通知保留待核对，不能凭金额猜新订单。静态收款码不会随窗口关闭而失效，不要再向已经过期的订单付款。重开窗口或刷新连接时会恢复当前订单：已付款显示下载入口，未付款恢复原短码和原截止时间；不会重新创建订单或延长有效期。本原型尚未提供完整的“我的已购”历史入口；需要重复一整轮测试时使用另一个 `-StateDirectory`，并保留旧目录用于对账。

查看脱敏监听状态：

```powershell
Get-Content -LiteralPath 'D:\code_file\pro_python\pet\zhuodazi\.local-review\local-market-transfer\bridge.status.json'
```

正常应有 `health: "ok"`、`running: true`、`baselineReady: true`、`lastPollSuccess: true`，且 `lastSuccessfulPollAt` 持续更新。`noticeBaselineReady` 和 `transferBaselineReady` 分别表示两路历史基线就绪；`noticeLastPollSuccess` 和 `transferLastPollSuccess` 分别表示本次读取成功。`candidateCount` 是捕获数，`deliveredCount` 是送到本地服务的数量，**不代表付款已核实或已发货**。`source_read_failed` 表示读取失败；分路错误可查看 `noticeLastErrorCode` / `transferLastErrorCode`；`http_*` 表示本地投递失败，队列会重试。

监听调用 wxlocal 的 `PaymentReader.notices()` 和 `PaymentReader.transfers()`，只处理官方支付通知和个人转账卡片，不采集或转发普通聊天正文，不发送微信消息。两个来源分别建立基线；在已有通知状态库上首次加入转账监听时，历史转账也不会回放。来源读取失败彼此隔离，微信正在写库导致的 BusyError 会有限重试；失败状态不会被显示成“没有付款”。重启复用原状态库，恢复后续增量与未完成投递。每次查询默认最多 200 条，`pollLimitSaturated` 只提示读满，不保证长时间离线或高流量时无遗漏。

候选保留最小必要支付字段，不持久化通知标题、详情或聊天正文。已有通知事件不会因解析器升级自动重放或修改。本地管理员可通过 `POST /api/local-market/payment-events/:id/reparse` 修正待核对候选的备注和分类：必须保留原事件、账号、金额、币种、交易编号、原时间和验证标记；服务端记录修正前后审计，不修改订单或发放权益，已批准记录不允许重解析。通知时间是微信消息时间，不能当作经过独立验证的实际交易时间。

个人转账原样事件重送仍按事件与交易标识去重。对于已经在有效期内接收、随后因规则升级而重新处理的原候选，只在原消息、观察及首次接收时间均有效且严格匹配时允许恢复过期订单并发放权益；不修改原时间，不放行首次接收就已超时的新消息。本次 `116PF` 仅精确重送已有两笔转账事件，不回放其他历史记录。
