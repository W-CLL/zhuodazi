# 3.5.8 Windows 内存优化补充验收

日期：2026-11-11（北京时间）。本页记录第三份本地候选阶段的 Windows 内存优化与测量。用户确认后已发布 3.5.8，正式构建及线上验证见 [发布记录](desktop-3.5.8-release-report.md)。

## 确认的问题与调整

1. 设置窗口关闭后只是隐藏，但仍在响应状态通知并刷新全部列表、日常统计与月历。现在隐藏或最小化时暂停界面刷新与界面时钟，恢复时读取最新状态；反馈草稿、选中页面等保留。
2. 即使日常页未显示，也会创建统计卡片和 42 格月历。现在仅显示时生成，退出该页或隐藏窗口时释放动态控件；记录与日期范围未变化时复用当前内容，新增心情等记录仍及时刷新。
3. 桌宠、来源、词库、剧本和大厅数据未变时仍重复绑定列表。现在比较显示数据，只在变化时重新绑定；仍可正确更新桌宠名称等变化。
4. 主桌宠隐藏后仍保留 GIF 帧并运行动画/运动计时器。现在释放动画缓存、停止运动计时器，显示时重新加载。隐藏时已经等待或随后请求的小剧场移动会结算，不会因计时器停掉而一直等待。
5. 小铺封面直接按原始像素解码。现在按 160 DIP × 屏幕缩放倍率限制封面最长边，保持原图比例，隐藏/最小化/卸载视图时释放。详情动画仍单独播放；设置内动画预览最小化时同样释放。

付款轮询和自动安装逻辑未更改；隐藏小铺后轮询继续。提醒、消息接收与授权服务继续由控制器负责。本轮未使用强制 GC 或工作集裁剪，没有降低桌宠 GIF 的帧率或颜色质量。

## 同一操作流程的三轮结果

采用真实窗口与控制器，默认 GIF、140 像素桌宠、离线合成身份及独立数据目录。分别运行第二份候选 DLL 与修改后 DLL，使用相同的检查程序、顺序和 GC 稳定步骤；以下为三轮中位数，单位 MiB（1,048,576 字节）。测试中的服务全部由内存响应替代，不连接生产。

| 场景 | 优化前 | 优化后 | 口径 |
| --- | ---: | ---: | --- |
| 只显示桌宠 | 92.29 | 92.17 | 进程私有内存，基本不变 |
| 初次打开设置 | 136.02 | 134.66 | 进程私有内存 |
| 查看日常后关闭设置 | 179.57 | 172.50 | 进程私有内存，约减少 3.9% |
| 设置与桌宠均隐藏 | 174.07 | 169.57 | 进程私有内存 |
| 五次隐藏/重新显示后 | 173.77 | 167.24 | 进程私有内存，约减少 3.8% |
| 外观页收到 30 次状态通知 | 15.50 | 1.92 | 期间累计分配量，约减少 87.6% |
| 日常页收到 30 次状态通知 | 40.71 | 2.01 | 期间累计分配量，约减少 95.1% |
| 设置隐藏时收到 30 次状态通知 | 41.00 | 0.53 | 期间累计分配量，约减少 98.7% |
| 设置最小化时收到 30 次状态通知 | 40.56 | 0.16 | 期间累计分配量，约减少 99.6% |

累计分配量会被垃圾回收，不等于永久泄漏，也不能当作整个软件内存的降幅。进程私有内存会包含运行时、WPF、原生图像和已申请但可复用的堆空间；任务管理器默认内存列与本表口径也不同。三轮中首次打开设置的单次结果存在波动，因此不宣称首次打开设置一定显著省内存。

## 验收重点与范围

已通过 Windows Release 编译、自包含发布、新增真实窗口生命周期检查、GIF 21 个文件/1,518 帧像素对照、日常存储 674 项、日常交互 UI 111 项及实时服务 23 项回归。发布版实包通过离线启动、二次启动、卸载阻止重开及准备卸载后主实例退出检查。封面测试覆盖横图/竖图、隐藏/最小化/恢复、丢失文件和解码后文件句柄释放；没有进行正式支付交易测试。

安装第三份候选后，打开“我们的日常”、切换其他页、最小化、关闭后重新打开，再隐藏/显示桌宠。记录与日期选择应正常，未发送反馈应保留，桌宠重新出现后继续播放。小铺封面应清晰且比例正常，付款后仍可自动安装、由用户自行启用。

本页测量针对 Windows。候选阶段未新增 macOS 内存优化或测量；后续发布时 macOS 两架构已通过云端原生构建及测试，详见发布记录。只显示桌宠时仍存在运行时与图形框架的基础开销；进一步明显降低设置窗口使用后的常驻占用，需要逐页延迟创建/释放设置界面，并明确处理草稿与后台交易任务的生命周期。
