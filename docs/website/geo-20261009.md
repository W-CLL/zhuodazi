# 官网 GEO 与搜索信息维护

本次覆盖首页、下载、激活、资源、关于、常见问题、6 篇手记以及归档、标签、分类页。目标是让用户和搜索服务读到清楚、一致、可追溯的产品说明，保留原有视觉风格与下载、购买流程。

## 内容来源

- `website/source/_data/product.yml`：产品名称、平台、主要功能、免费体验、激活价格和官方入口。用于 FAQ 页导语、首页价格、下载页授权说明、激活价卡与购买链接、SoftwareApplication / Offer 数据，以及文本阅读文件。
- `website/source/_data/questions.yml`：常见问题正文、锚点与进一步阅读入口。FAQ HTML、FAQPage 结构化数据、完整文本答案共用这一份数据。
- `website/source/_posts/*.md`：文章的标题、摘要、作者、发表时间、实际修改日期与完整说明。保留历史更新文章的版本上下文，最新安装包以下载页为准。
- 营销段落和文章中的自然语言仍在对应 EJS / Markdown 内。价格或授权策略变化时，除数据文件外，应搜索 `6.88`、`7 天`、`两台设备`，同步更新这些可见段落和测试期望。

确认口径：基础陪伴免费；首次 7 天进阶体验；6.88 元一次购买永久激活，不按月续费；一组 6 位激活码最多授权同一账号的两台设备；私人搭子由双方独立账号各自正式激活后，用 8 位搭子码绑定。平台差异、联网与后台限制、未兑换码有效期在对应说明中保留。

## 构建生成的内容

`website/lib/discovery.cjs` 负责元信息、可追溯的日期和安全 JSON-LD 序列化；`website/scripts/discovery.js` 注册 Hexo helper、文本生成器与 sitemap 生成逻辑。

- 每页独立标题、描述、canonical 与社交分享元信息。标签、分类、年份、分页有明确身份；404 保持 noindex。
- 使用关联的 Organization、WebSite、SoftwareApplication、WebPage 实体；文章有 BlogPosting，列表有 CollectionPage / ItemList，内页有 BreadcrumbList。FAQPage 仅用于实际展示完整问答的 FAQ 页。
- 免费基础陪伴与付费激活分别建 Offer；不编造评分、评论或下载量。
- `/sitemap.xml` 来自实际生成的可索引 HTML 路由，覆盖中文分类、标签及未来归档分页，排除 404/noindex。已移除旧手写 sitemap，后续不要在 source 中另建同名文件。
- `/llms.txt` 是官方页面和文章索引；`/llms-full.txt` 包含产品信息、FAQ 和公开文章 Markdown 正文，并标明来源。两者随正常构建更新，不需要手工维护。
- `robots.txt` 保持原有通配允许规则和 sitemap 地址，没有新增针对模型训练的授权规则。
- 首页关闭文章分页；归档、分类、标签仍支持分页且展示真实翻页链接。

文章仅使用 front matter 中明确声明的 `updated`。未声明时回退 `date`，不把本地文件时间或 CI checkout 时间当作内容更新时间。只在实际修改内容时更新 `updated`，不要定时批量刷新日期。

## 检查与发布

在 `website/` 下运行：

```sh
npm ci
npm run check
```

`check` 执行 Node 单元测试、完整 Hexo 构建、全站生成产物校验；现有 Website CI 已调用这个命令。普通 `npm run build` 也会生成 sitemap 与两份文本文件。

在仓库根目录运行 `python scripts/check-release-consistency.py` 检查发布信息一致性。视觉验收应覆盖手机、桌面、深色模式以及关闭 JavaScript 的 FAQ / 资源 / 下载页；动态资源目录在无 JavaScript 时展示明确说明，下载链接保留官方固定入口。

本次改动完成于本地，发布需走仓库现有部署流程。发布后检查 `/faq/`、`/activate/`、`/sitemap.xml`、`/llms.txt` 与 `/llms-full.txt` 的线上响应。若已有搜索站长平台账号，可在部署后提交自动 sitemap。

这些文件和结构化数据有助于清楚呈现官方事实，但搜索引擎和 AI 服务是否抓取、引用或展示富结果由各服务决定；不承诺排名或收录结果。
